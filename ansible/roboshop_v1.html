roboshop_v1 Overview

roboshop_v1 is my first version of deploying roboshop with Ansible. Every component has its own playbook, and I run the playbooks one by one. It doesn't use roles yet; that comes in roboshop_ansible_v2.

The project is built in two steps:

  • v1: make it work. The aim is to get working deployment scripts for every component, so the whole shop runs end to end.
  • v2: make it best. Once everything works, the same deployment is rewritten using Ansible best practices: roles, reusable code, cleaner variables and secured credentials.

The Ansible features used here (variables, conditions, loops, inventory, ansible.cfg) are explained on the Ansible Concepts page.

Source code: github.com/MadireddyManojKumar/ansible_roboshop/roboshop_v1

Architecture

roboshop is a small online shop split into separate components. Each component runs on its own EC2 instance, and every instance has a DNS name like catalogue.manojkumar.blog, so the components find each other by name instead of by IP address.

  • frontend runs nginx. It serves the website and forwards /api/<service> calls to the right service.
  • catalogue lists products from mongodb. user handles logins with mongodb and redis.
  • cart keeps carts in redis and asks catalogue for product details.
  • shipping reads cities from mysql and talks to cart. payment talks to cart and user, then puts the order on rabbitmq.
  • dispatch picks orders up from rabbitmq.

What's in the repository

Every file has its own section in the sidebar, cleaned up for reading, with a comment on each task. Passwords and download URLs are masked.

  • roboshop_ec2_instances.yaml: creates the EC2 instances and their Route 53 DNS records, or deletes them with action=delete.
  • inventory.ini: one group per component, using the DNS names, plus the SSH user.
  • ansible.cfg: Ansible settings for this folder, such as YAML-formatted output.
  • ms-roboshop-<component>.yaml: one playbook per component, 11 in total, for example ms-roboshop-mongodb.yaml.
  • <service>.service.j2: systemd service templates. Ansible fills in the host names, for example {{ mongo_host }} in catalogue.service.j2.
  • roboshop.conf.j2: the nginx config template for frontend.
  • mongo.repo, rabbitmq.repo: package repository files copied to the servers.
  • ec2_instance_creation_output.yaml: a saved copy of the EC2 creation output, which I used to find where the IP address sits in the result.

How a deployment runs

  1. Create the servers. Run the EC2 playbook once. It creates an instance per component and points <component>.manojkumar.blog to it.
  2. Databases first: mongodb, redis, mysql, rabbitmq. The services connect to them when they start, and catalogue loads its products into mongodb.
  3. Then the services: catalogue, user, cart, shipping, payment, dispatch.
  4. frontend last, once everything it forwards to is running.

Inside one playbook: catalogue

Each service playbook follows the same pattern. For catalogue, the steps are: install Node.js 24, create the roboshop system user, download the code into /app, install its dependencies, copy the systemd service file, load the products into mongodb and start the service.

The service file is a template. The mongo_host variable from the playbook is filled in when Ansible copies it: 

  - name: copy systemd service file
    template:
      src: catalogue.service.j2
      dest: /etc/systemd/system/catalogue.service
Environment=MONGO_URL="mongodb://{{ mongo_host }}:27017/catalogue"

Loading products should happen only once. The playbook counts the products already in mongodb and loads the data only when the count is 0, so running it again doesn't add duplicates: 

  - name: check products loaded in mongodb
    command: mongosh --host "{{ mongo_host }}" --quiet --eval 'db.getSiblingDB("catalogue").products.countDocuments()'
    register: products_count

  - name: print product_count
    debug:
      msg: "{{ products_count }}"


  - name:  load schema for catalogue microservice
    shell: "mongosh --host {{ mongo_host }} < /app/db/master-data.js"
    when: products_count.stdout|int == 0

From working (v1) to best (v2)

v1 met its aim: every component deploys and the shop works. Getting there also showed what makes the scripts hard to maintain, and that is what v2 improves:

  • Repeated code. The service playbooks repeat the same steps: create the roboshop user, prepare /app, download the code and set up systemd.
  • Host names in every playbook. Names like mongodb.manojkumar.blog are written in each playbook's vars, so a domain change means editing many files.
  • Many commands in the right order. Deploying means running 11 playbooks by hand, in order.
  • Plain-text passwords. Passwords sit in the inventory, playbooks and templates, where anyone who can read the repository can see them.

roboshop_ansible_v2 fixes this in two ways:

  • Roles. The shared steps are written once, and a single main.yaml deploys any component by its name.
  • Secured credentials, in two ways. Secrets are encrypted with Ansible Vault, so the repository only holds the encrypted text. Secrets are also kept in an AWS secret store, so they live in AWS, not in the code, and the playbook fetches them only when it runs.

roboshop_ec2_instances.yaml

Creates the roboshop EC2 instances and a Route 53 DNS record for each one, like mongodb.manojkumar.blog. Run it with action=delete to remove everything. Runs on the control node itself (hosts: local).

Run it:

ansible-playbook -i inventory.ini roboshop_ec2_instances.yaml
ansible-playbook -i inventory.ini roboshop_ec2_instances.yaml -e action=delete
- name: roboshop-mongodb create ec2 instances
  connection: local
  hosts: local
  vars:
    ami_id: ami-0055977a6e828a4f4
    instance_type: t3.micro
    instances: ["mongodb", "redis", "mysql", "rabbitmq", "catalogue", "user", "cart", "shipping", "payment", "frontend"]
    domain_name: manojkumar.blog
    action: create
  tasks:
    # create one EC2 instance per component (when action is create)
    - name: create ec2 instances
      amazon.aws.ec2_instance:
        name: roboshop-{{item}}
        image_id: "{{ ami_id }}"
        instance_type: "{{instance_type}}"
        security_groups:
          - "roboshop-{{item}}"
          - "roboshop-common"
        region: us-east-1
      loop: "{{instances}}"
      when: action == "create"
      register: ec2_instance_creation_output

    # point <component>.manojkumar.blog to the new instance's IP
    - name: route 53 record creation
      amazon.aws.route53:
        state: present
        zone: "{{domain_name}}"
        record: "{{item.item}}.{{domain_name}}"
        type: A
        ttl: 1
        value: "{{item.instances[0].public_ip_address}}"
        overwrite: true
      loop: "{{ec2_instance_creation_output.results}}"
      when: action == "create"

    # delete the DNS records (when action is delete)
    - name: route 53 record deletion
      amazon.aws.route53:
        state: absent
        zone: "{{domain_name}}"
        record: "{{item}}.{{domain_name}}"
        type: A
        ttl: 1
      loop: "{{instances}}"
      when: action == "delete"

    # terminate the EC2 instances (when action is delete)
    - name: delete ec2 instances
      amazon.aws.ec2_instance:
        name: roboshop-{{item}}
        state: absent
        region: us-east-1
        wait: false
      loop: "{{instances}}"
      when: action == "delete"

ms-roboshop-mongodb.yaml

Installs MongoDB and lets the other servers connect to it. catalogue and user store their data here.

Run it:

ansible-playbook -i inventory.ini ms-roboshop-mongodb.yaml
- name: Roboshop MongoDB deployment script using ansible
  hosts: mongodb
  become: true
  tasks:
    # add the MongoDB repo so dnf can find the packages
    - name: setup mongodb repo file
      copy:
        src: mongo.repo
        dest: /etc/yum.repos.d/mongo.repo

    # install the MongoDB server
    - name: install mongodb
      ansible.builtin.package:
        name: mongodb-org
        state: present

    # start mongod and start it on every boot
    - name: start mongodb
      ansible.builtin.service:
        name: mongod
        state: started
        enabled: yes

    # check that the service is running
    - name: verify mongodb status
      ansible.builtin.command: systemctl is-active mongod
      register: mongodb_status

    # print the status (active / inactive)
    - name: display mongodb status
      debug:
        var: mongodb_status.stdout

    # listen on all addresses so other servers can connect
    - name: configure mongodb bind_ip
      replace:
        path: /etc/mongod.conf
        regexp: "127.0.0.1"
        replace: "0.0.0.0"

    # restart so the new bind_ip takes effect
    - name: restart mongodb
      ansible.builtin.service:
        name: mongod
        state: restarted

    # check the service again after the restart
    - name: verify mongodb status after restart
      ansible.builtin.command: systemctl is-active mongod
      register: mongodb_status_after_restart

    # print the status after the restart
    - name: display mongodb status after restart
      debug:
        var: mongodb_status_after_restart.stdout

    # check that MongoDB is listening on port 27017
    - name: verify mongodb listening port
      shell: netstat -tulnp | grep 27017
      register: mongodb_port_status

    # print the port check result
    - name: display mongodb listening port status
      debug:
        var: mongodb_port_status.stdout

    # done
    - name: success message
      debug:
        msg: "MongoDB deployment completed successfully."

ms-roboshop-redis.yaml

Installs Redis 7 and lets user and cart connect to it.

Run it:

ansible-playbook -i inventory.ini ms-roboshop-redis.yaml
- name: configure redis server
  hosts: redis
  become: yes
  tasks:
    # choose Redis 7 from the dnf modules
    - name: enable redis 7
      command: dnf module enable redis:7 -y

    # install Redis
    - name: install redis
      package:
        name: redis
        state: present

    # listen on all addresses so other servers can connect
    - name: allow remote connections
      replace:
        path: /etc/redis/redis.conf
        regexp: '127.0.0.1'
        replace: '0.0.0.0'

    # turn off protected mode, which blocks remote clients
    - name: disable protected mode
      lineinfile:
        path: /etc/redis/redis.conf
        regexp: '^#?protected-mode yes'
        line: 'protected-mode no'

    # restart Redis with the new config and start it on every boot
    - name: enable and start redis
      service:
        name: redis
        state: restarted
        enabled: yes

    - name: create rabbitmq user
      community.rabbitmq.rabbitmq_user:
        user: roboshop
        password: "*****"
        vhost: /
        configure_priv: .*
        read_priv: .*
        write_priv: .*
        state: present

ms-roboshop-catalogue.yaml

Installs Node.js, deploys the catalogue app, loads the products into MongoDB (only once) and starts the service.

Run it:

ansible-playbook -i inventory.ini ms-roboshop-catalogue.yaml
- name: configure catalogue microservice
  hosts: catalogue
  become: yes
  vars:
    catalogue_app_user: roboshop
    mongo_host: mongodb.manojkumar.blog
  tasks:
    # turn off the default Node.js version
    - name: disable default nodejs
      command: dnf module disable nodejs -y

    # choose Node.js 24
    - name: enable nodejs version 24
      command: dnf module enable nodejs:24 -y

    # install Node.js
    - name: install nodejs
      package:
        name: nodejs
        state: present

    # read the installed Node.js version
    - name: verify nodejs version
      command: node -v
      register: nodejs_version

    # print the Node.js version
    - name: print nodejs version
      debug:
        msg: "Nodejs version is {{ nodejs_version.stdout }}"

    # create the roboshop system user that runs the app
    - name: create roboshop user
      user:
        name: roboshop
        create_home: no
        system: yes
        home: /app
        comment: "roboshop system user"
        shell: /sbin/nologin

    # remove any old copy of the app
    - name: remove default application directory
      file:
        path: /app
        state: absent

    # create an empty /app folder
    - name: create application directory
      file:
        path: /app
        state: directory

    # download the catalogue code
    - name: download catalogue microservice
      get_url:
        url: https://*****
        dest: /tmp/catalogue.zip

    # unzip the code into /app
    - name: unzip catalogue microservice
      unarchive:
        src: /tmp/catalogue.zip
        dest: /app
        remote_src: yes

    # install the app's Node.js packages
    - name: install nodejs dependencies
      community.general.npm:
        path: /app

    # create the systemd service file from the template
    - name: copy systemd service file
      template:
        src: catalogue.service.j2
        dest: /etc/systemd/system/catalogue.service

    # add the MongoDB repo, needed for the mongosh client
    - name: copy mongo repo to destination folder
      copy:
        src: mongo.repo
        dest: /etc/yum.repos.d/mongo.repo

    # install mongosh to talk to MongoDB
    - name: install mongodb client
      package:
        name: mongodb-mongosh
        state: present

    # count the products already in MongoDB
    - name: check products loaded in mongodb
      command: mongosh --host "{{ mongo_host }}" --quiet --eval 'db.getSiblingDB("catalogue").products.countDocuments()'
      register: products_count

    # print the product count
    - name: print product_count
      debug:
        msg: "{{ products_count }}"

    # load the products only if there are none yet
    - name: load schema for catalogue microservice
      shell: "mongosh --host {{ mongo_host }} < /app/db/master-data.js"
      when: products_count.stdout|int == 0

    # make systemd read the new service file
    - name: daemon reload systemd
      systemd_service:
        daemon_reload: true

    # start catalogue and start it on every boot
    - name: Ensure the application is enabled and running
      ansible.builtin.service:
        name: catalogue
        state: started
        enabled: true

roboshop.conf.j2

The nginx config for frontend. It sends each /api/<service> call to the right server and serves the website. 

server_tokens off;

# nginx gives every request a unique id ($request_id). It is sent to the
# services and back to the browser, so one click can be traced on all servers
add_header X-Request-Id $request_id always;
add_header X-Content-Type-Options nosniff always;
add_header X-Frame-Options SAMEORIGIN always;
add_header Referrer-Policy strict-origin-when-cross-origin always;

gzip on;
gzip_types text/css application/javascript application/json image/svg+xml;
gzip_min_length 1024;

# common settings for all backend calls
proxy_http_version 1.1;
proxy_set_header Host              $host;
proxy_set_header X-Real-IP         $remote_addr;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Request-Id      $request_id;
# the services send the id back too, nginx already adds it, so hide theirs
proxy_hide_header X-Request-Id;
proxy_connect_timeout 5s;
proxy_read_timeout    30s;   # 504 if a service takes longer than this

# the trailing / removes the /api/<service> part:
# /api/catalogue/products -> https://*****
location /api/catalogue/ { proxy_pass http://{{catalogue_host}}:8080/; }
location /api/user/      { proxy_pass http://{{user_host}}:8080/; }
location /api/cart/      { proxy_pass http://{{cart_host}}:8080/; }
location /api/shipping/  { proxy_pass http://{{shipping_host}}:8080/; }
location /api/payment/   { proxy_pass http://{{payment_host}}:8080/; }

# when nginx itself cannot reach a service, answer in JSON like the services do.
# errors a service returns on its own (its 404, 503...) pass through untouched
error_page 502 = @bad_gateway;
error_page 504 = @gateway_timeout;
location @bad_gateway {
    default_type application/json;
    return 502 '{"message":"service not reachable (502 Bad Gateway from nginx)"}';
}
location @gateway_timeout {
    default_type application/json;
    return 504 '{"message":"service did not answer in time (504 Gateway Timeout from nginx)"}';
}

# nginx's own connection counters
location = /health {
    stub_status on;
    access_log off;
}

# product images, missing ones fall back to the placeholder
location /images/ {
    expires 1h;
    try_files $uri /images/placeholder.jpg;
}

# file names in /assets contain a hash of their content, so they can be cached forever
location /assets/ {
    expires max;
    try_files $uri =404;
}

# React handles all other paths (/product/RMC, /cart ...) in the browser,
# so every unknown path returns index.html
location / {
    expires -1;
    try_files $uri $uri/ /index.html;
}
